# 局域网协议设计 v1(2026-09-08,成员 5)

> 评审通过后,Day 2 由成员 5 落地 LanHost / LanClient 骨架;成员 4 的大厅 UI 按本文档来做。

## 1. 总体架构

- **主机是唯一规则裁决方**:主机持有唯一 `GameEngine`,所有命令先经 `legalCommands` 校验再 `apply`。
- **客户端只发命令、只收自己视角的快照**:主机按座位调用 `snapshotFor(seat)` 给每个客户端各发各的,**绝不下发他人手牌**。
- 主机本机玩家与远端玩家走同一条命令通道,规则上一律平等。

## 2. 端口与帧格式

- 固定端口 **46888**。
- 传输层 TCP;应用层帧 = **4 字节 big-endian 长度前缀 + JSON 字节(UTF-8)**。
- 长度合法区间 `[1, 1_048_576]`;越界立即断开连接(防恶意/脏数据)。
- 消息之间无分隔符,长度前缀即边界。

## 3. 消息类型表

Day 2 实现成 Jackson 多态 sealed interface(`@JsonTypeInfo` + `@JsonSubTypes`,`@type` 字段区分子类型):

| type | 方向 | 载荷 | 说明 |
|---|---|---|---|
| JOIN | 客户端→主机 | 无 | 请求加入,必须是连接后第一条消息 |
| ROOM_SNAPSHOT | 主机→客户端 | RoomSnapshot | 房间变化时广播 |
| START_GAME | 主机→客户端 | GameType + 座位 | 开局,告知该客户端被分配的座位 |
| GAME_SNAPSHOT | 主机→客户端 | GameSnapshot | 每次状态变化,按座位各发各的 |
| SUBMIT_COMMAND | 客户端→主机 | GameCommand | 玩家操作 |
| ERROR | 主机→客户端 | 错误码 | ROOM_FULL / EXPECTED_JOIN / INVALID_COMMAND … |
| GAME_ENDED | 主机→客户端 | 原因 | GAME_OVER / PLAYER_DISCONNECTED / HOST_SHUTDOWN |

## 4. 座位与命名

- 主机 = `SEAT_1` =「玩家 1(主机)」;加入者按连接顺序 =「玩家 2」「玩家 3」「玩家 4」。
- **跑得快满 3 人、骗子酒馆满 4 人**;满员后第 4/5 个连接者收 `ERROR(ROOM_FULL)` 并断开。
- 不做账号与昵称,显示名一律由主机分配。

## 5. 时序规则

1. 人数未齐主机不能开局(开局按钮禁用 + 协议层拒绝)。
2. 开局前断开 → 释放座位、广播 `ROOM_SNAPSHOT`。
3. 开局后任一远端断开 → 广播 `GAME_ENDED(PLAYER_DISCONNECTED)`,本局结束,不做断线重连。
4. 主机关闭 → 向所有客户端广播 `GAME_ENDED(HOST_SHUTDOWN)`。

## 6. 线程规则

- 网络线程**只投递命令**,不改游戏状态;所有 `engine.apply` 只在 JavaFX 线程执行(引用 `docs/architecture.md`)。
- 主机收到 `SUBMIT_COMMAND` 后经 `Platform.runLater` 转交引擎;引擎 `apply` 后对每个座位重新生成快照并逐个下发。
